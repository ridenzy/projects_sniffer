# Security policy

## Supported versions

Project Sniffer is in pre-1.0 development. Security maintenance focuses on
current development code; there is no guaranteed support window for older
revisions or a published security response-time commitment.

## Reporting a vulnerability

Do not post vulnerability details, exploits, real secrets, private project
reports, or confidential source in public issues, pull requests, or discussions.

If GitHub shows **Report a vulnerability** on the
[repository advisories page](https://github.com/ridenzy/projects_sniffer/security/advisories),
use it to send a private report.

If the private-reporting control is unavailable, open a
[non-sensitive issue](https://github.com/ridenzy/projects_sniffer/issues)
asking the maintainers for a secure reporting method. Do **not** describe the
vulnerability or attach evidence in that issue. No separate security email
address is published by this policy.

## Report contents and safe research

Where possible, share the affected version or commit, impact, expected and
observed behavior, and a minimal synthetic reproduction through the private
channel. Exclude real credentials and private customer or project data.

Investigate only systems you own or are authorized to test. Do not execute
unsafe proofs against third-party projects or production environments.

## Review and coordinated disclosure

Maintainers review reports as capacity allows and may coordinate fixes and
public disclosure with the reporter. No response deadline, fix deadline, or
bug bounty is promised. Security fixes and release claims must be verified
before being described as available.

For ordinary, non-sensitive bugs, see [SUPPORT.md](SUPPORT.md).
